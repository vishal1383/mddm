# Learning Anchors That Unlock Parallel Decoding

## Two-page GSM8K method and results

**Model:** LLaDA-8B-Instruct | **Train/Test:** 7,473/1,319 GSM8K examples | **Canvas:** 128 tokens

## Abstract

Masked diffusion models predict every unfinished position in parallel, but normal
confidence decoding commits only the safest predictions. We exploit the observation
that one informative token, called an **anchor**, can make several other positions
confident. Our offline cache explicitly measures this effect: for every plausible
anchor, place its gold token, rerun frozen LLaDA, and count the increase in correct
positions above 0.95 confidence. The best anchor and **all correct high-confidence
tokens available after placing it** are committed together to form the next cached
state. Training then rolls the actual adaptive decoder for two frozen-teacher
cycles and teaches a LoRA student to expose the second cycle from the earlier
canvas. At inference, one student forward commits up to two plausible text anchors
plus every safe confidence-threshold token from the same logits.

On the full GSM8K test set, this increases completion tokens per model forward
from **5.449 to 7.246**, measured canvas throughput from **26.90 to 33.24
tokens/s**, and reduces evaluation time from **104.6 to 84.7 minutes**. Accuracy is
**70.20% versus 68.84%** for frozen base under the identical decoder. Thus the main
result is a 33.0% logical-throughput gain and 19.1% wall-clock reduction without an
observed accuracy regression.

## 1. Motivation and failed first formulation

The original full-test intervention showed that out-of-order information matters:
GSM8K accuracy increased from 54.9% with no gold anchor to 66.7% with one and
68.8% with two. More anchors eventually hurt because later IG ranks contained
unlikely fragments, operators, and isolated digits. In one trajectory, an
isolated `0` changed a correct `2640` into `26400`.

Our first trainer directly supervised greedy-IG gold anchors with
`L_place + 0.25 L_order + L_gold_CE` and a Gaussian centered near each gold
position. It failed because the Gaussian leaked the location, the order loss was
almost always zero, and oracle anchors produced canvases the model would not choose
at inference. The replacement below keeps the anchor-unlock insight but aligns
training targets with the deployed decoder.

## 2. New approach

Instead of training directly on oracle IG order, we separate **anchor discovery**
from **decoder supervision**. Gold interventions are used once to build causal
cache states that show which tokens an anchor unlocks. Frozen base LLaDA then
generates the actual future decoder actions from those states, and LoRA distills
the future action into the earlier canvas. Inference needs no gold answer, IG
calculation, cache lookup, or separate anchor-policy network.

### 2.1 Offline anchor-unlock cache

The cache is generated once from GSM8K train completions with frozen base LLaDA.
It supplies blank and partially completed states; it is never regenerated by the
changing LoRA. Gold is used only in this offline stage to measure whether a
candidate truly unlocks correct predictions.

### Algorithm 1: Generate one cached trajectory

```text
Input: prompt q, gold completion y, frozen base B,
       tau_cache=0.95, candidate ratio rho=0.70
x <- fully masked completion canvas
save x

while an alphabetic gold token remains masked:
    Run B(q,x).
    A <- alphabetic masked positions i satisfying
         P_B(y_i|q,x,i) >= rho * max_r P_B(y_r|q,x,r)
    if A is empty: stop

    for each i in A:
        x_i <- x with gold anchor y_i inserted at i
        Run B(q,x_i)
        U_before(i) <- correct masked positions >=0.95 under x, excluding i
        U_after(i)  <- correct masked positions >=0.95 under x_i, excluding i
        W_after(i)  <- incorrect masked positions >=0.95 under x_i
        gain(i)     <- |U_after(i)| - |U_before(i)|

    i* <- lexicographic argmax of
          (gain, |U_after|, -|W_after|, P_B(y_i|q,x,i), -position)

    save x with anchor y_i* inserted
    x[i*] <- y_i*
    for every j in U_after(i*): x[j] <- y_j
    save this expanded x as the next trajectory state
```

The key transition is the last three lines: the cache does not place only one
anchor. It places the selected anchor and every correct high-confidence token
available after that intervention, then repeats from the expanded state. The score
uses after-minus-before so an anchor is rewarded for newly revealed work. The
0.70 criterion is relative to the best candidate probability, preventing an
extremely unlikely oracle token from winning solely through intervention value.

### 2.2 Decoder-aligned lookahead training

Each optimizer step always includes the blank canvas and samples up to three
unique partial states from Algorithm 1. Cached states provide anchor-rich coverage,
but the final labels are recomputed online from frozen base predictions.

### Algorithm 2: Two-cycle adaptive teacher and student loss

```text
for each starting state x:
    Disable LoRA and run frozen base B(q,x).
    a1 <- highest-confidence alphabetic prediction below text tau=0.90;
          if none exists, use the leftmost unfinished prediction.
    burst1 <- all other nonnumeric predictions >=0.90
              plus numeric predictions >=0.99 from the same logits.
    x1 <- x with a1 and burst1 committed.

    Run frozen base B(q,x1).
    Select a2 and burst2 by the same rule, forming x2.

    Enable LoRA and run student S_theta(q,x) once on the original x.
    L_future <- -log P_theta(token(a2) at position(a2) | q,x)
    L_rank   <- softplus(best rival score
                         - weaker score among {a1,a2} + 0.1)
    L_KL     <- mean KL(P_B(.|q,x,i) || P_theta(.|q,x,i))
                over masked positions other than future position a2.

L_total = mean(L_future) + mean(L_rank) + 5 mean(L_KL)
Update LoRA only; clip gradient norm to 1.0.
```

`L_future` pulls the second-cycle anchor back to the first state. `L_rank` ensures
both anchors rank among positions that the decoder can actually commit; predicting
the right token at a low-ranked position is insufficient. KL preserves base-model
behavior elsewhere. Teacher actions are model predictions rather than gold tokens.

Training uses one GSM8K epoch, rank-8 LoRA (`alpha=16`, dropout 0.05) on
`q_proj,k_proj,v_proj,attn_out`, BF16, AdamW at `3e-5`, and no policy network.

### 2.3 Adaptive inference

### Algorithm 3: Same-forward anchors and confidence burst

```text
x <- fully masked 128-token canvas
while masks remain:
    Run S_theta(q,x) once over the full canvas.
    E <- alphabetic top-token predictions with confidence below 0.90.
    a1 <- highest-confidence candidate in E.
    Accept a2 only if P(a2)>=0.60 and P(a2)/P(a1)>=0.85.
    If E is empty, commit the leftmost unfinished prediction.
    From the same logits, also commit every remaining nonnumeric token >=0.90
    and every remaining numeric token >=0.99.
```

There is no extra model call after placing an anchor. Training has pulled the
future cycle into the current logits, so anchors and their safe parallel work can
be committed together. Alphabetic anchors and the stricter numeric threshold guard
against the stray-token failure found in the IG experiment.

## 3. Full-test results

### Main matched adaptive result

| Metric | Frozen base | Ours | Improvement |
|---|---:|---:|---:|
| Accuracy | 68.84% | **70.20%** | **+1.36 pp** |
| Tokens/forward | 5.449 | **7.246** | **+33.0%** |
| Forwards/example | 23.49 | **17.66** | **-24.8%** |
| Canvas tokens/s | 26.90 | **33.24** | **+23.6%** |
| Eval clock | 104.6 min | **84.7 min** | **-19.1%** |

The model commits 33.0% more tokens per forward, uses 24.8% fewer summed logical
forwards, and is 19.1% faster by wall clock. This shows that we can exploit anchor
information to improve decoding speed without losing accuracy in this full-test
comparison, matching the earlier intuition that the extra training cost can be
recovered during inference. Threshold bursts explain 94.4% of the token-rate
increase, supporting the intended mechanism. The +1.36 accuracy-point estimate is
positive but not statistically conclusive; efficiency is the primary claim.

### Fixed-k controls

| Model and decoder | Accuracy | Tokens/forward | Forwards/example | Eval clock |
|---|---:|---:|---:|---:|
| Base, standard confidence `k=1` | 75.44% | 1.000 | 128 | 172.9 min |
| Base, fixed `k=2` | 73.01% | 2.000 | 64 | 132.1 min |
| Anchor-lookahead LoRA, fixed `k=2` | 73.01% | 2.000 | 64 | 152.7 min |

These tables use different decoders. Fixed `k=1` gives 75.44% at 1.000
token/forward. Under fixed `k=2`, our step-6,000 model ties base exactly at 73.01%
(963/1,319), with 105 wins and 105 losses. The primary matched comparison uses
the identical adaptive decoder: ours reaches 70.20% and 7.246 tokens/forward
versus 68.84% and 5.449 for base. Thus the gain is decoder-aligned rather than a
generic top-2 improvement.

## 4. Next steps

**Higher horizon and dynamic programming:** roll three or four teacher cycles and
search over small anchor sets using `safe tokens unlocked - mistakes - forward
cost`, then distill the best short plans without a separate RL policy.

**Token2Token correction:** train on model-generated corrupted canvases and add
`wrong token -> corrected token`, `wrong token -> MASK`, and suffix-deletion
actions so committed stray anchors such as the final `0` can be repaired.
